# 修复方案：参数解析问题

## 问题描述

从日志分析发现，MorphProtocol 参数在 WireGuardPlugin 中丢失，原因是：

1. JavaScript 传递 `useMorphProtocol: true`
2. Capacitor 将其转换为整数 `1`
3. `call.getBool("useMorphProtocol")` 无法解析整数，返回 `nil`
4. 使用默认值 `false`，导致 MorphProtocol 配置分支不执行

## 证据

### 日志证据
```
// React 传递
useMorphProtocol: true

// WireGuardPlugin 接收到
AnyHashable("useMorphProtocol"): 1  // 整数！

// 但是没有看到这条日志
🔐 WireGuardPlugin: MorphProtocol 已启用  // 缺失！
```

### 代码证据
```swift
let useMorphProtocol = call.getBool("useMorphProtocol") ?? false
// getBool 无法解析整数 1，返回 nil，使用默认值 false
```

---

## 修复方案

### 方案 1：改进参数解析（推荐）✅

修改 `packages/wireguard-plugin/ios/Plugin/WireGuardPlugin.swift` 第 56 行：

```swift
// 修改前
let useMorphProtocol = call.getBool("useMorphProtocol") ?? false

// 修改后 - 同时支持布尔值和整数
let useMorphProtocol: Bool = {
    // 首先尝试作为布尔值解析
    if let boolValue = call.getBool("useMorphProtocol") {
        return boolValue
    }
    // 如果失败，尝试作为整数解析
    if let intValue = call.getInt("useMorphProtocol") {
        return intValue != 0
    }
    // 都失败则返回 false
    return false
}()

// 添加调试日志
print("🔍 WireGuardPlugin: useMorphProtocol raw: \(call.options["useMorphProtocol"] ?? "nil")")
print("🔍 WireGuardPlugin: useMorphProtocol parsed: \(useMorphProtocol)")
```

### 方案 2：确保使用 NSObject 类型

修改 `saveConfiguration` 方法（第 240 行左右）：

```swift
// 修改前
var providerConfig: [String: Any] = [
    "wg_config": config
]

if useMorphProtocol {
    providerConfig["useMorphProtocol"] = true
    providerConfig["morphEncryptionKey"] = morphEncryptionKey
    providerConfig["morphServerHost"] = morphServerHost
    providerConfig["morphServerPort"] = morphServerPort
    providerConfig["morphLayerCount"] = morphLayerCount
    providerConfig["morphPaddingLength"] = morphPaddingLength
}

// 修改后 - 使用 NSObject 类型
var providerConfig: [String: NSObject] = [
    "wg_config": config as NSString
]

if useMorphProtocol {
    providerConfig["useMorphProtocol"] = NSNumber(value: true)
    providerConfig["morphEncryptionKey"] = morphEncryptionKey as NSString
    providerConfig["morphServerHost"] = morphServerHost as NSString
    providerConfig["morphServerPort"] = NSNumber(value: morphServerPort)
    providerConfig["morphLayerCount"] = NSNumber(value: morphLayerCount)
    providerConfig["morphPaddingLength"] = NSNumber(value: morphPaddingLength)
    
    print("🔐 WireGuardPlugin: MorphProtocol 配置已添加")
    print("🔐 WireGuardPlugin: providerConfig keys: \(providerConfig.keys)")
}
```

## 完整修复代码

### 文件：`packages/wireguard-plugin/ios/Plugin/WireGuardPlugin.swift`

#### 修改 1：connect 方法（第 56-68 行）

```swift
// 解析 MorphProtocol 选项 - 改进的参数解析
let useMorphProtocol: Bool = {
```

## 故障排除

### 问题：修复后仍然显示"未启用"

**检查**：
1. 确认修改已保存
2. 重新构建项目（Clean Build Folder）
3. 检查日志中的 `useMorphProtocol parsed` 值

### 问题：providerConfiguration 仍然只有 wg_config

**检查**：
1. 确认 `if useMorphProtocol` 分支被执行
2. 检查类型转换是否正确
3. 查看 `providerConfig keys` 日志

### 问题：Network Extension 仍然收不到参数

**可能原因**：
- 配置未正确保存到系统
- 需要删除旧配置重新创建

**解决**：
```swift
// 在 saveConfiguration 中，先删除旧配置
NETunnelProviderManager.loadAllFromPreferences { managers, error in
    // 删除所有旧配置
    managers?.forEach { $0.removeFromPreferences { _ in } }
    
    // 然后创建新配置
    let manager = NETunnelProviderManager()
    // ... 设置配置 ...
}
```

## 总结

**根本原因**：Capacitor 将 JavaScript 的 `true` 转换为整数 `1`，而 `getBool` 无法解析。

**修复方法**：改进参数解析逻辑，同时支持布尔值和整数。

**额外改进**：使用 NSObject 类型确保配置正确保存。

**验证方法**：通过日志确认参数正确解析和保存。

修复后，MorphProtocol 功能应该可以正常工作。
